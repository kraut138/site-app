"6. 공사 확인 음성요청 내역" 탭 추가 업데이트

수정 내용
- 기존 "6. 검측·NCR·표준 공종" 탭 이름을 "7. 검측·NCR·표준 공종"으로 변경했습니다.
- "5. 현장용어/은어 DB" 탭과 "7. 검측·NCR·표준 공종" 탭 사이에 "6. 공사 확인 음성요청 내역" 탭을 새로 추가했습니다.
- 새 탭은 하도급 반장이 모바일 모드에서 남긴 음성 보고(말한 글이 저장된 voiceReports 기록)를 전부 모아,
  그 안의 동·호수 표현을 자동으로 판별(기존 "3. 각 호실 정보" 탭에서 쓰는 것과 같은 판별 로직)해서
  "동 / 층 / 호수" 칸으로 묶어 보여줍니다.
  - 각 칸에는 그 호실에 쌓인 기록 건수가 표시됩니다.
  - 칸을 클릭하면 그 호실의 모든 기록(말한 그대로의 원문, 표준 용어로 순화한 문장, 자동 요약, 작성자, 시간, 공종)을
    카드 목록으로 모아서 확인할 수 있습니다.
  - 동·호수가 분명하게 판별되지 않는 기록(여러 호실이 함께 언급되었거나 호실 표현이 없는 경우)은
    "호실 미확인" 칸에 따로 모아, 어떤 기록도 빠짐없이 확인할 수 있게 했습니다.
  - 이 탭은 기존 관리 탭들과 같이 관리자(감리단) 권한에서만 보입니다.

중요 - 음성 "녹음" 관련 제한 사항
- 이 시스템은 원래부터 음성을 녹음 파일(오디오)로 저장하지 않고, 말한 내용을 텍스트로 변환해서만 저장하도록 되어 있습니다.
  (voiceReports 기록에 오디오 파일이 없고 rawText/요약 문장만 있습니다.)
- 따라서 이번에 추가한 탭에서도 "음성 재생"은 제공되지 않고, 말한 내용을 텍스트로 모아서 확인하는 형태로 만들었습니다.
  실제 오디오 파일까지 재생하고 싶으시면 녹음 저장 방식 자체를 바꾸는 추가 작업이 필요하니 말씀해 주세요.

수정/추가된 파일 (5개, 기존 저장소의 같은 경로에 그대로 덮어쓰면 됩니다)
- src/platform/tabs.js        (탭 이름/순서 수정)
- src/data.js                 (새 탭 접근 권한 추가)
- src/App.jsx                 (새 탭 화면 연결)
- src/styles.css              (새 탭 전용 디자인 추가)
- src/components/VoiceRequestsBoard.jsx   (신규 파일 - 새 탭의 화면 전체)

기존 저장소에 적용하는 방법 (GitHub Desktop)
1. 이 ZIP의 압축을 풉니다. 압축을 풀면 "src" 폴더가 나옵니다.
2. 기존 GitHub 저장소 폴더(사이트 코드가 있는 폴더)를 엽니다.
3. 이 ZIP 안의 src 폴더를 기존 저장소의 src 폴더 위에 그대로 덮어씁니다.
   - platform/tabs.js, data.js, App.jsx, styles.css는 기존 파일을 덮어쓰는 것이고,
   - components/VoiceRequestsBoard.jsx는 새로 추가되는 파일입니다.
   - 다른 파일(예: components 폴더의 다른 화면 파일들)은 이 ZIP에 없으니 그대로 두면 됩니다. 지우지 마세요.
4. GitHub Desktop을 열어 "Changes" 탭에서 5개 파일(수정 4개 + 신규 1개)이 바뀐 것을 확인합니다.
5. 커밋 메시지를 입력합니다. 예: "6.공사 확인 음성요청 내역 탭 추가, 기존 6번 탭을 7번으로 이동"
6. main 브랜치에 Commit → Push 합니다.
7. GitHub 저장소 페이지의 Actions 탭에서 "Deploy to GitHub Pages" 작업이 성공(초록색 체크)하는지 확인합니다.
   - 이 저장소는 push할 때 자동으로 빌드(vite build) 후 배포되는 구조입니다.
   - 혹시 실패(빨간 X)하면 Actions 로그에 한국어로 원인이 안내되니 그대로 보내주시면 봐드리겠습니다.
8. 배포가 끝나면 사이트를 Ctrl+Shift+R(강력 새로고침)로 새로고침한 뒤, 관리자 계정으로 "6. 공사 확인 음성요청 내역" 탭을 확인합니다.

검증 범위
- 5개 파일 모두 실제 번들러(esbuild)로 전체 앱 코드와 함께 빌드해서 문법 오류나 깨진 import가 없는지 확인했습니다.
- CSS 파일도 중괄호 짝이 정확히 맞는지 확인했습니다.
- 다만 이 작업 환경에는 Firebase 연결이나 실제 브라우저 화면이 없어서, 실제 배포 후 화면이 의도한 대로 보이는지는
  GitHub Actions 배포 후 사이트에서 직접 확인해 주셔야 합니다.
